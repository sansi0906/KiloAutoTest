## P0-严重（立即修复）

### 问题1：价格输入框允许输入负数

| 项目 | 内容 |
|------|------|
| **模块** | 下单流程 |
| **优先级** | P0-严重 |
| **问题描述** | 客户订单/记录订单的价格输入框可以输入负数（如-100），无前端校验 |
| **影响** | 可能导致订单金额计算错误，甚至造成资金损失 |
| **复现步骤** | 1. 进入购物车 → 2. 全选商品 → 3. 点击"生成订单" → 4. 选择"客户订单" → 5. 选择客户 → 6. 在价格输入框输入"-100" |
| **预期结果** | 价格输入框应限制为正数，输入负数时应拦截并提示 |
| **实际结果** | 负数可正常输入并提交 |
| **建议方案** | 1. 前端：输入框设置 `inputType="number"`，监听输入过滤负号<br>2. 后端：提交时校验价格必须 > 0<br>3. 双重保障，避免被绕过 |

### 问题2：价格输入框允许输入非数字字符

| 项目 | 内容 |
|------|------|
| **模块** | 下单流程 |
| **优先级** | P0-严重 |
| **问题描述** | 价格输入框可以输入"abc"等非数字字符，无输入类型限制 |
| **影响** | 可能导致订单数据异常，后端处理错误 |
| **复现步骤** | 1. 进入下单流程 → 2. 在价格输入框输入"abc" |
| **预期结果** | 价格输入框应只允许数字和小数点 |
| **实际结果** | 非数字字符可正常输入 |
| **建议方案** | 1. 输入框设置 `inputType="numberDecimal"`<br>2. 添加 TextWatcher 实时过滤非数字字符<br>3. 提交时二次校验 |

## P1-高（优先修复）

### 问题3：购物车商品不默认选中，合计初始为￥0.00

| 项目 | 内容 |
|------|------|
| **模块** | 购物车 |
| **优先级** | P1-高 |
| **问题描述** | 首次进入购物车，所有商品都未选中，合计显示￥0.00。用户可能误以为购物车异常或商品已失效 |
| **影响** | 用户体验差，可能导致用户困惑，误以为购物车功能异常 |
| **复现步骤** | 1. 进入购物车 → 2. 查看合计金额 |
| **预期结果** | 商品应默认选中，合计显示真实总价 |
| **实际结果** | 商品未选中，合计显示￥0.00，需手动点击"全选"才能看到真实金额 |
| **建议方案** | 1. 商品加入购物车时默认选中状态为 true<br>2. 或在合计旁显示提示"请选择要购买的商品" |

### 问题4：使用"生成订单"替代"结算"按钮

| 项目 | 内容 |
|------|------|
| **模块** | 购物车 |
| **优先级** | P1-高 |
| **问题描述** | 常规电商App使用"结算"按钮，乐云台使用"生成订单"。文案差异增加用户学习成本 |
| **影响** | 用户习惯的结算流程断裂，增加学习成本 |
| **复现步骤** | 1. 进入购物车 → 2. 全选商品 → 3. 查看底部按钮 |
| **预期结果** | 使用行业通用的"结算"按钮文案 |
| **实际结果** | 按钮文案为"生成订单" |
| **建议方案** | 1. 改为"结算"按钮<br>2. 或保留"生成订单"但添加副标题说明"选择订单类型" |

### 问题5：客户审核-点击"通过"无确认弹窗

| 项目 | 内容 |
|------|------|
| **模块** | 客户管理 |
| **优先级** | P1-高 |
| **问题描述** | 待审核客户详情页，点击"通过"按钮后直接执行审核操作，无二次确认弹窗 |
| **影响** | 审核是重要操作，误触可能导致错误审核通过不合格客户 |
| **复现步骤** | 1. 进入客户管理 → 2. 切换到"待审核"Tab → 3. 点击待审核客户 → 4. 点击"通过"按钮 |
| **预期结果** | 点击"通过"后应弹出确认弹窗："确认通过该客户？" |
| **实际结果** | 直接执行审核操作，无确认弹窗 |
| **建议方案** | 添加 AlertDialog 二次确认，包含"确认通过"和"取消"按钮 |

### 问题6：订单详情-终止订单无确认弹窗

| 项目 | 内容 |
|------|------|
| **模块** | 订单管理 |
| **优先级** | P1-高 |
| **问题描述** | 订单详情页，点击"终止订单"按钮后直接执行，无二次确认弹窗，也无需填写终止原因 |
| **影响** | 终止订单是破坏性操作，误触可能终止正常订单，且无法追溯终止原因 |
| **复现步骤** | 1. 进入订单列表 → 2. 点击有"终止订单"按钮的订单 → 3. 点击"终止订单" |
| **预期结果** | 1. 弹出确认弹窗："确认终止该订单？"<br>2. 要求填写终止原因 |
| **实际结果** | 直接执行终止操作，无确认弹窗，无需填原因 |
| **建议方案** | 1. 添加确认弹窗<br>2. 添加"终止原因"输入框（必填）<br>3. 终止后记录原因到订单日志 |

### 问题7：客户详情页缺少"拨打电话"按钮

| 项目 | 内容 |
|------|------|
| **模块** | 客户管理 |
| **优先级** | P2-中 |
| **问题描述** | 客户详情页显示了联系人、联系电话等信息，但没有"拨打电话"快捷按钮。测试了入驻客户、驳回客户，均无拨号入口 |
| **影响** | 营销人员需手动复制号码拨打，影响工作效率 |
| **复现步骤** | 1. 进入客户管理 → 2. 点击任意客户 → 3. 查看详情页 |
| **预期结果** | 详情页应有"拨打电话"按钮，点击调起系统拨号 |
| **实际结果** | 无拨号入口 |
| **建议方案** | 在联系电话旁添加拨号图标按钮，点击后调起 `Intent.ACTION_CALL` 或 `ACTION_DIAL` |

### 问题8：快速切换Tab后页面状态异常

| 项目 | 内容 |
|------|------|
| **模块** | 导航 |
| **优先级** | P2-中 |
| **问题描述** | 快速连续点击底部Tab（客户/购物车/订单/首页）多次后，页面停留在客户页，无法回到首页。需重启App才能恢复 |
| **影响** | 影响用户体验，可能导致用户以为App崩溃 |
| **复现步骤** | 1. 快速点击 客户→购物车→订单→首页 各5次 → 2. 检查首页状态 |
| **预期结果** | 快速切换Tab后，最后点击的Tab页面应正常显示 |
| **实际结果** | 页面停留在客户页，点击首页Tab无反应 |
| **建议方案** | 1. 优化Tab切换的状态管理逻辑<br>2. 添加防抖机制（debounce），避免快速点击导致状态混乱<br>3. 确保每次Tab切换的事务完整性 |

### 问题9：记录订单缺少"交易时间"字段

| 项目 | 内容 |
|------|------|
| **模块** | 下单流程 |
| **优先级** | P2-中 |
| **问题描述** | 记录订单定义为"记录真实且已发生的交易订单"，但表单中没有交易时间/成交时间字段 |
| **影响** | 无法准确记录交易发生的时间，与记录订单的业务含义不符 |
| **复现步骤** | 1. 购物车→全选→生成订单 → 2. 选择"记录订单" → 3. 检查表单字段 |
| **预期结果** | 记录订单表单应包含"交易时间"字段，支持选择日期和时间 |
| **实际结果** | 表单只有选择客户、发货选项、价格输入，无交易时间 |
| **建议方案** | 添加"交易时间"字段，使用 DatePicker + TimePicker，默认值为当前时间 |
